# 安装、更新与数据恢复

当前为开发预览包。完整 v1 尚待平台真实验收，请先在工作台中确认预览内容、登录账号和任务结果。

0.1.2 使用名称“zMatrix · 自媒体矩阵工作台”，停在最终发布前，最终按钮由你在原站手动点击。更新后，“平台与备份”右上角应显示 `v0.1.2 · 开发预览`；旧的发布任务也不会自动提交。

## 首次加载到 Edge

1. 保留整个源码目录，或将 `zMatrix-edge-0.1.2.zip` 解压到固定目录。
2. 打开 `edge://extensions`，启用“开发人员模式”。
3. 点击“加载解压缩的扩展”，选择包含 `manifest.json` 的目录。源码构建时是 `.output/edge-mv3`。
4. 点击扩展工具栏中的“zMatrix”，打开独立标签页工作台。
5. “平台与备份”中逐站连接，检查当前账号。平台登录、绑定或开通操作在原站完成。
6. 设置备份目录，或先手动导出一次 ZIP 备份。

连接平台会请求该站点的访问权限，用于原生编辑器操作及已登记文章的数据读取。仅连接你需要使用的平台。浏览器权限弹窗由用户确认。

## 更新

1. 在当前版本中导出备份。
2. 保留 `extension-identity.json` 和 manifest 中的 `key`。它们固定扩展身份，不包含登录凭据或私钥。产品更名不会更换扩展 ID、原数据库或备份格式。
3. 使用新版本替换固定目录中的扩展文件，或在同一源码目录执行 `npm ci`、`npm run build`。
4. 在 `edge://extensions` 点击该扩展的“重新加载”。不要先卸载扩展；卸载可能清除扩展存储。
5. 重新打开工作台，检查稿件和任务记录，再主动继续待执行任务。

## 备份

- “本地已保存”表示已写入 IndexedDB；“备份已完成”才表示写入独立备份目录。
- 有变更时，工作台在空闲后写入 `zMatrix-auto.zip`；上一份写入 `zMatrix-previous.zip`。首次升级时可从旧的 `tonggao-auto.zip` 承接上一份备份；原文件保留。
- 浏览器关闭后停止自动备份；目录权限失效时提示重新授权，本地编辑继续可用。
- 手动导出的 ZIP 包含正文、素材、平台版本、发布记录、指标、评论和任务，不包含平台登录状态。
- 恢复前检查结构与素材校验和，再一次性合并。已有本地记录不会被旧备份覆盖；若要恢复为备份原样，使用一个全新的扩展数据环境。

## 结果待核实

“等待手动发布”表示已核对内容并停在最终按钮前；“发布设置待核对”表示仍有设置或步骤未验证，不能算验收通过。使用任务卡的“回到原标签页”继续，避免用新标签页丢失尚未保存的发布设置。手动发布后再点击“核实原站结果”，此操作不会刷新待发布页面。

网络超时不代表提交失败。先打开任务保留的原站标签页或链接，再点击“核实结果”。未能核实前不要创建相同内容的新发布任务。

若原标签页已关闭且没有可定位的远端链接，先在原站查找，再通过“文章数据 → 登记文章”记录链接并关联母稿。当前开发版尚不能在丢失远端标识时自动找回原稿。

## 已知未完成项

平台封面上传、部分发布弹窗字段、小红书长文章入口与图文保存、平台数据和历史回复读取仍须在真实账号上验证并补齐。开发包会在无法识别或核对时停止，人工接管不计为自动流程通过。详见 `docs/acceptance.md`。
