# 安装、更新与数据恢复

当前为开发预览包。完整 v1 尚待平台真实验收，请先在工作台中确认预览内容、登录账号和任务结果。

v0.5.0 使用名称“zMatrix · 自媒体矩阵工作台”，停在最终发布前，最终按钮由你在原站手动点击；旧的发布任务也不会自动提交。平台连接位于侧栏“平台账号”，数据备份与软件更新位于“设置”中。博客园恢复受保护的自动填入，发布和保存草稿均需原站人工点击。

## 首次加载到 Edge

1. 保留整个源码目录，或将 `zMatrix-edge-0.5.0.zip` 解压到固定目录。
2. 打开 `edge://extensions`，启用“开发人员模式”。
3. 点击“加载解压缩的扩展”，选择包含 `manifest.json` 的目录。源码构建时是 `.output/edge-mv3`。
4. 点击扩展工具栏中的“zMatrix”，打开独立标签页工作台。
5. 在“平台账号”中点击“一键连接全部”或逐站连接，再检查当前账号。平台登录、绑定或开通操作在原站完成。
6. 设置备份目录，或先手动导出一次 ZIP 备份。

连接平台会请求该站点的访问权限，用于原生编辑器操作及已登记文章的数据读取。仅连接你需要使用的平台。浏览器权限弹窗由用户确认。

## 更新

**0.3.0 及更早版本需先手动升级到 0.4.0 一次，才能在工作台内安装后续更新。** 更新检测从 0.2.0 起提供，0.1.2 不具备检测功能；如果“仅正式版”已开启，开发预览版不会提示。

“设置 → 软件更新”提供可选更新检测。扩展默认每 6 小时检查 GitHub 发布版本，浏览器重新启动或扩展后台唤醒时也会补查到期的检查；关闭工作台标签页后仍由浏览器的扩展后台负责检查，浏览器完全关闭时不会运行。普通网页预览仅在页面打开时检查。

- 默认接收正式版与开发预览；可以切换为仅正式版。
- 可关闭自动检查，随时手动“检查更新”。检查失败或被限流会显示原因，不会误报为最新版本。
- 发现新版本时显示通知和下载入口；可以选择稍后处理。检测只读取版本信息，不下载、安装或重载扩展。
- 当前分发形式为解压扩展。0.4.0 起提供下述“立即更新”流程，也可以仅下载安装包并手动替换。
- 新增 `alarms` 权限用于后台检测，以及 `https://api.github.com/*` 的访问权限用于读取本仓库的公开 Release；请求不携带稿件、登录状态或本地内容。
- 0.2.1 新增 `declarativeNetRequestWithHostAccess`，只在已授权博客园访问的前提下，为工作台新开的任务标签页阻止意外提交。规则在用户亲自点击原站提交控件或关闭标签页时移除；不会修改其他原站标签页。
- 0.4.0 新增 `https://release-assets.githubusercontent.com/*`，用于从 GitHub Release 下载公开扩展包。检测和下载不携带稿件、平台 Cookie 或本地备份。

### 在工作台内安装更新

1. 在“设置 → 软件更新”点击“设置目录”，选择 Edge **当前加载**、直接包含 `manifest.json` 的扩展文件夹，并授予读写权限。程序会核对扩展身份、版本以及是否为实际加载目录，另一个副本不能用于更新。
2. 发现新版本后，保存并关闭其他工作台标签页，完成发布队列中执行中、等待人工确认或结果待核实的任务，然后点击“立即更新至 v…”。
3. 程序下载并核验安装包，在安装目录的 `zmatrix-update-backup/update-…/` 保存 `program.zip`、`workspace.zip` 和 `recovery.json`，随后替换文件并自动重新加载。重新打开的软件更新页会再次核验文件并显示完成结果。

首次设置和浏览器要求重新授权时需要你操作目录权限弹窗。后续安装仍由每次点击“立即更新”触发，不会在自动检测时安装。更新期间请保持工作台打开；此时编辑和后台任务暂停。

`workspace.zip` 是完整内容备份，可在“数据与备份”恢复；它不包含平台登录状态或目录授权。`program.zip` 只保留本次覆盖的旧程序文件，配合 `recovery.json` 用于撤回文件替换。其他文件、旧资源和已有备份保留，备份不会自动删除。

写入失败会尝试恢复原程序。关闭页面、断电或权限失效导致中断时，重新打开工作台，按提示取消尚未写入的更新、恢复上一版程序或继续完成重载。若扩展已无法打开，可按下节手动重装完整 Release 包；保留原扩展与安装目录，不要卸载。

安装入口适用于支持 File System Access 的 Edge 解压扩展。缺少 GitHub 校验摘要、包内文件清单，或扩展权限／运行范围变化的版本需要手动更新；商店安装版应交由浏览器商店管理。源码用户请运行 `npm run package` 生成完整文件清单，单独运行 `npm run build` 不满足此要求。

### 手动更新与首次升级

1. 在当前版本中导出备份。
2. 保留 `extension-identity.json` 和 manifest 中的 `key`。它们固定扩展身份，不包含登录凭据或私钥。产品更名不会更换扩展 ID、原数据库或备份格式。
3. 使用新版本替换固定目录中的扩展文件，或在同一源码目录执行 `npm ci`、`npm run build`。
4. 在 `edge://extensions` 点击该扩展的“重新加载”。不要先卸载扩展；卸载可能清除扩展存储。
5. 重新打开工作台，检查稿件和任务记录，再主动继续待执行任务。

0.3.0 保留原扩展 ID、数据库名称与权限，首次打开会升级数据库结构，保留已有稿件和记录。更新后继续使用 0.3.0 或更新版本；旧版 ZIP 备份仍可恢复，新备份还包含回收站状态与防重凭据。

0.4.0 沿用 v2 数据库结构与原扩展身份。原生目录授权和跨版本自动重载的实机验收边界见 [更新验证记录](verification-updater-2026-09-30.md)。

## 备份

- “本地已保存”表示已写入 IndexedDB；“备份已完成”才表示写入独立备份目录。
- 有变更时，工作台在空闲后写入 `zMatrix-auto.zip`；上一份写入 `zMatrix-previous.zip`。首次升级时可从旧的 `tonggao-auto.zip` 承接上一份备份；原文件保留。
- 浏览器关闭后停止自动备份；目录权限失效时提示重新授权，本地编辑继续可用。
- 手动导出的 ZIP 包含正文、素材、平台版本、发布记录、指标、评论和任务，不包含平台登录状态。
- 恢复前检查结构与素材校验和，再一次性合并。已有本地记录不会被旧备份覆盖；若要恢复为备份原样，使用一个全新的扩展数据环境。

## 结果待核实

“等待手动发布”表示已核对内容并停在最终按钮前；“发布设置待核对”表示仍有设置或步骤未验证，不能算验收通过。使用任务卡的“回到原标签页”继续，避免用新标签页丢失尚未保存的发布设置。手动发布后再点击“核实原站结果”，此操作不会刷新待发布页面。

网络超时不代表提交失败。先打开任务保留的原站标签页或链接，再点击“核实结果”。未能核实前不要创建相同内容的新发布任务。

若原标签页已关闭且没有可定位的远端链接，先在原站查找，再通过“数据与互动 → 文章数据 → 登记文章”记录链接并关联母稿。当前开发版尚不能在丢失远端标识时自动找回原稿。
